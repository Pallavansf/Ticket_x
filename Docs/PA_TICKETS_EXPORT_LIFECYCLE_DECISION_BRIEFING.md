## Decisions that must be approved together

1. Historical output semantics, row-level evidence, invalidation, and legacy-artifact handling form one authorization decision. Downloads cannot be restored with only a permission check.
2. Audit event catalogue, actor identity, transaction ownership, outage policy, and retry identity form one audit contract. Actor and transaction decisions cannot be separated from failure semantics.
3. Expiry cutoff, retention, worker lease, storage concurrency, retry/dead-letter, and cleanup audit form one cleanup contract. Cleanup must never restore access.
4. Provider migration approval depends on the selected authorization/audit/cleanup contracts and preservation/rollback evidence.
5. E2E release approval depends on successful authorization, audit, cleanup, and provider gates.

## Verified facts versus recommendations

Verified source facts:

- Exports currently persist RUNNING, COMPLETED, or FAILED; expiry is derived from ExpiresAt during reads.
- Download performs owner and current permission checks but fails closed because artifact-level row authorization is unavailable.
- Report generation applies current permission and scope filtering.
- LocalFileStorage atomically publishes files but best-effort deletes them.
- PersistentBackgroundWorker has durable leasing, retries, attempts, correlation, and exhausted states.
- Existing audit chaining uses AuditRow, AuditTransaction, and AuditChainCoordinator; cross-context/storage atomicity is unverified.

Recommendations in this briefing are not approvals. Deployed schema, foreign keys, provider behavior, storage distribution, and owner policy are unresolved assumptions until separately verified.

Downloads remain fail-closed until authorization evidence is complete. Cleanup remains disabled until lease/race, retry, storage, monitoring, and audit evidence is complete. Audit completeness requires provider-backed persistence and chain evidence. Database execution requires target, baseline, backup, rollback, and preservation evidence. Full E2E requires hosted API and Angular/browser results after those gates.
